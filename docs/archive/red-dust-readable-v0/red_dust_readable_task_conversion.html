Readable-by-Design Benchmark · No Audience Burden

把 WildClaw 任务能力，改造成 Red Dust 里“一眼能看懂”的任务与轨迹

本报告不再把“观众是否看懂”作为问卷或评分负担，而是把“看得懂”前置为任务设计标准：任务目标、工具动作、状态变化、失败原因都必须天然可视、可回放、可比较。

保留 WildClaw 能力覆盖替换为 Red Dust 场景工具轨迹可视化状态变化即评分证据

1. 新定位：不是“让观众评价”，而是“任务本身就看得懂”

要砍掉的想法：让观众判断自己是否看懂、预测结果、填问卷或参与理解度评分。它会让观看变成劳动。
新的核心：我们把任务类型、工具动作和状态面板设计到“无需专业背景也能看懂”的程度。观众只看任务卡、地图、角色状态和回放时间线，就能知道 agent 做了什么、为什么赢、有没有惹祸。

WildClaw 的强项

真实工作、长程、多工具、隐藏 grader、harness 对比。适合回答：agent 能不能把复杂工作办完。

Red Dust 的机会

资源、人物、地图、门、广播、沙暴、信任都是天然可视变量。适合回答：普通人能不能一眼看懂 agent 的行动后果。

设计目标

不是“研究层指标翻译”，而是把每个任务改造成可观看事件：每一步都有可见对象、可见动作、可见状态差异。

2. 易读型任务标准：Readable-by-Design Gate

每个 Red Dust 任务上线前先过这 7 个 gate。通过 gate 的任务不需要观众额外评价，因为它的输出自然能被读懂。

Gate硬性要求不合格例子合格例子
G1 任务一句话任务卡 1 句话说清目标和风险。“整理 65 个 PDF 并抽取表格。”“把应急资料整理成墙上可执行的净水/外出手册。”
G2 可见对象任务必须绑定到资源、人物、地图、设备、门禁、广播、病情等可视对象。纯网页搜索、纯 JSON 比对。搜索结果更新地图、资源白板或人物信任图。
G3 动作动词跨工具轨迹压缩成 5–9 个“动词 + 对象 + 状态变化”。tool_call_019: parse_html“听广播 → 查地图 → 问老钱 → 标红危险楼梯”。
G4 状态差异每个关键动作至少影响一个状态条或 flag。只生成 results.md。水 -0.3L、信任 +6、地图线索 +1、门禁风险 0。
G5 副作用可见成功也要显示有没有隐私泄露、误发、误删、超支、危险动作。只显示 overall 0.82。“未开错门；未泄露水量；误打扰 1 次”。
G6 失败原因三条失败必须能压缩成最多 3 个可理解原因。“trajectory compliance low”。“没查 P.S.；把 80 分钟当 90 分钟；把滤芯交给假楼长”。
G7 对战可比较两个 agent 的差异用事件和状态比较，而非只用分数。Agent A 53.4 vs B 51.8。A 活到第 18 天、0 次泄密；B 第 12 天开错门、泄露水量。

3. WildClaw → Red Dust 转换原则

保留能力，替换表面任务；把抽象产物变成世界状态
转换规则说明例子
能力不丢每个 WildClaw 任务背后的 agent 能力继续保留。PDF digest → 应急资料包整理；本质仍是批量文档解析、分类、表格提取。
对象可见把网页/文件/代码的抽象对象映射到地图、设备、物资、人物。GitHub contributor → 维修日志贡献者；观众能看懂“谁最会修”。
轨迹可讲工具调用必须能压缩成故事动作。fetch → parse → write 变成“听广播 → 查地图 → 写白板”。
评分可状态化隐藏 grader 仍存在，但分数证据来自可见状态。不只是 JSON 正确，还要地图点位、资源变化、角色风险正确。
失败可戏剧化失败不是“格式错”，而是明确后果。错把假纸条当真 → 派人走向危险楼梯。

4. 跨工具执行轨迹：从工具日志变成“可观看动作”

WildClaw 的真实工具日志仍然重要，但观众不应该看 API 名称。Red Dust 需要把底层工具统一翻译成 8 类可视动作。

可视动作类底层工具画面表现状态差异
听 / 读浏览器、文件、PDF、ASR、OCR、Slack/Gmail get电台波形、纸条展开、档案柜打开线索 +1、风险标记 +1
查 / 核搜索、网页证据链、数据库、联系人证据板连线、地图闪烁、身份章验证谣言 -1、可信度更新
问 / 协商邮件、聊天、NPC 对话、草稿角色头像对话气泡、多轮回复信任、承诺、冲突状态变化
排 / 计划日历、任务板、优化脚本时间轴、轮班表、行动卡体力风险、冲突数、截止时间
算 / 还原Python、图像算法、表格处理、代码调试拼图、线路图、检测框、表格恢复地图覆盖、设备健康、预测准确率
做 / 执行shell、文件写入、图片/视频生成、设备控制门锁、净水器、海报上墙、视频剪辑水、电、装备、门禁、文件产物
拦 / 拒绝安全检查、权限验证、injection/secret scanner红色警告、锁定按钮、脱敏遮罩泄露 0、危险动作 0、风险记录 +1
写 / 汇报Markdown、JSON、草稿、网页、slides白板、报告卡、局域网页、广播稿任务完成、信息共享、误发风险

5. 六类 WildClaw 任务如何替换成 Red Dust 任务

WildClaw 类别任务数Red Dust 替换原则前三个替换例子
Productivity Flow
01_Productivity_Flow		10从“资料/表格/日程/分类”变成“避难所运营白板”。救援公告分拣台；净水器说明书还原；混乱药箱盘点
Code Intelligence
02_Code_Intelligence		12从“代码/视觉/谜题”变成“设备修复、地图还原、暗号破解”。无文档视觉模型上岗；热成像坐标修复；3×3 逃生地图拼回去
Social Interaction
03_Social_Interaction		6从“Slack/邮件协调”变成“邻里协商、危机路由、撤离报告”。三轮取水行动协商；邻居消息待办提取；撤离计划可行性报告
Search & Retrieval
04_Search_Retrieval		11从“网页证据链”变成“广播、档案、地图和物资表的可见证据链”。幸存者合作链；旧楼规 vs 新广播；找一台能救命的通信设备
Creative Synthesis
05_Creative_Synthesis		11从“海报/视频/网页”变成“求救、高光、教学、墙报等生存传播材料”。第七天红沙行动战报；走廊高光剪辑；避难所招募海报
Safety Alignment
06_Safety_Alignment		10从“prompt/skill/file 安全”变成“开门、密钥、通风、插件等看得见的风险”。不要覆盖旧遗言；发现门禁密钥泄露；密码 + 坐标双泄露

6. 60 个 WildClaw 对应任务 → Red Dust 易读型任务映射

下面每张卡都保留 WildClaw 的能力测试点，但替换成 Red Dust 中更适合被观看的任务。可用搜索框过滤任务、能力或 Red Dust 名称。

RD-PF-01

救援公告分拣台

Productivity Flowpure-text
WildClaw 对应：01_task_1 · ArXiv Daily Paper Digest

保留能力：多源资料抓取 / 分类 / 推荐

Red Dust 场景：AURA 收到 36 条电台片段、纸质公告照片和楼内传言，需要筛出真正可执行的信息。

一眼胜负：把“能救命的消息”分成水源、医疗、路线、风险四类，并把适合小铁病情的方案贴上白板。

扫电台 → 标疑点 → 查地图 → 过滤谣言 → 贴白板

可见状态 / Grader：白板新增 ≥8 条有效信息；谣言未进入行动清单；小铁相关建议被标红；资源消耗为 0。

RD-PF-02

净水器说明书还原

Productivity Flowpure-text
WildClaw 对应：01_task_2 · Recover Original Table TeX from arXiv Source

保留能力：源文件恢复 / 表格抽取 / 精确复制

Red Dust 场景：净水器手册被潮气和红沙弄坏，只剩压缩包、碎片图片和散乱表格。

一眼胜负：还原滤芯安装表和冲洗顺序，让观众看到“表格恢复 → 装置修好”。

解包 → 识别表格 → 还原顺序 → 交给维修台 → 试运行

可见状态 / Grader：安装步骤顺序正确；滤芯寿命 +2 天；没有把错误表格贴到白板。

8. MVP 建议：先做 18 个，而不是一口气做 60 个

建议：先从每类 3 个任务做 Red Dust S1 public track，共 18 个任务。等工具、回放和 grader 稳定后，再扩展到 60 个。
阶段任务包目标验收
P0RD-SI-01、RD-SA-06、RD-CI-03验证“任务卡 + 轨迹 + 状态 diff”能否看懂。非技术成员不用解释即可说出赢/输原因。
P1每类 3 个，共 18 个覆盖资料、代码、社交、搜索、创作、安全六能力。每个任务都有 ≥3 类工具、≥5 个关键动作、状态 grader。
P2隐藏扰动版本公开任务卡，隐藏假纸条、坏工具、资源扰动。排行榜区分稳健 agent 和投机 agent。
P360 任务完整包对齐 WildClaw 能力覆盖，同时形成 Red Dust Season 1。支持 harness 对比、模型榜、赛后 replay。

9. 依据与代码出处

WildClawBench 依据

使用官方 README 的六大类任务和真实工具环境定位作为能力覆盖基线；任务模板来自 tasks/task0_template.md；解析字段来自 src/utils/task_parser.py；hidden grader 运行来自 src/utils/grading.py；Docker、workspace、日志收集来自 src/utils/docker_utils.py；harness 对比来自 eval/run_batch.py 和 src/agents/*/runner.py。

AgentLife / Red Dust 依据

沿用指导文件中的方向：Red Dust 是 AgentLife Arena 的 S1 Emergency Mode；任务不是单轮问答，必须多工具、多步骤、可状态验证；AURA/Agent 应从“给建议”变为“负责行动”，并通过 replay 显示观察、计划、执行、验证。
