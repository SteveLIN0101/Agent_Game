Agent Benchmark 任务分类的三个学派

文献综述与案例分析 · 为红沙 (Red Dust) Agent-Benchmark 重设计做铺垫
DOC 17  |  DATE 2026-05-12  |  STATUS 文献综述 · 不含设计决策  |  FOLLOWUP 18_REDDUST_BENCHMARK_REDESIGN_CN（待）

§0 摘要 · 为什么需要一个分类框架

OpenClaw 当前的六职业划分（software_engineer / data_analyst / ui_designer / technical_writer / localization / digital_humanities）需要一句话能回答两个问题：

  1. 我们在测什么？—— 任务桶的命名决定了 benchmark 的"叙事"。说"我们测六个职业"和说"我们测六类能力"是两种完全不同的承诺。
  2. 为什么是这些桶，不是别的？—— 这是评审/合作方/用户最容易追问的问题。

2024–2026 的 agent benchmark 文献给出三种成体系的回答方式。本文档逐一拆解它们的任务选择逻辑（task selection — 任务从哪来）和分桶逻辑（allocation — 任务如何被归类），并用具体 benchmark 做 case study。

三派一句话定义
职业派 任务来源 = 真实工作任务库 (O*NET) · 分桶单位 = 职业角色 · 代表 = TheAgentCompany
能力派 任务来源 = 单一能力探针 · 分桶单位 = 基础能力轴 · 代表 = HELM / GAIA
用户行为派 任务来源 = 实测产品日志 · 分桶单位 = 高频意图 macro-category · 代表 = NBER w34255 / Anthropic Index
三派任务流向图

§1 核心张力

三派的根本分歧是一个哲学问题："agent 能力"是什么？

  • 职业派：能力 = 能否在一个真实工作位置上完成被分配的任务。这是"agent 能不能被雇佣"的视角。
  • 能力派：能力 = 底层的、可分解、可组合的认知/操作原语。这是"agent 大脑里有什么"的视角。
  • 用户行为派：能力 = 能否满足人类真实问出的请求。这是"agent 对用户有没有用"的视角。

三个视角都对，但任务选择和评分逻辑会被各自的回答完全决定。我们逐个拆。

§2 学派一 · 职业派 (Role-based)

§2.1 核心命题与任务选择

命题

把 agent 当作"可雇佣的工人"来测，任务从 真实职业的工作清单 里抽样。

理论支点是美国劳工部维护的 O*NET（Occupational Information Network），它把 1,016 个职业拆成"工作活动 (work activities)"、"任务声明 (task statements)" 和"知识/技能/能力" 三层。O*NET 不是为 AI 写的，是为职业咨询和劳动力市场分析写的，所以它声称的合法性来自"真实工作"。

任务选择逻辑（task selection）

  • 采样源：O*NET 的 task statement 列表（每职业 20–40 条），或对应的 SOC（Standard Occupational Classification）工作描述。
  • 具体化：把抽象任务（"分析销售数据"）转写为一个 可在沙箱中执行 的实例（"用这个 CSV 算 Q3 客户流失率，写到 report.md"）。
  • 真实素材：常常引入真实公司流程片段（Slack 截图、Wiki 页面、Jira 工单）以增加生态效度。

§2.2 分桶逻辑（allocation）

分桶单位 = 职业 (role / occupation)。一个 agent 在某个桶里的得分 = "如果让它做这份工作的考核任务，它能完成多少"。

属性典型做法
桶的数量5–20（受 O*NET SOC 大类约束）
桶内任务数量常常不等量，由职业重要性 / 数据可得性决定
跨桶关系不强制正交 ── 允许"用 SQL 做财务"既在财务桶又在数据分析桶 (mostly 用单一标签解决)
评分聚合桶内取平均，全局取桶平均或加权平均

§2.3 案例 · TheAgentCompany (CMU 2024)

CASE 1 TheAgentCompany — 模拟一家完整软件公司 CMU · Xu, Neubig et al. · NeurIPS 2025
论文
arXiv 2412.14161 · project site
任务规模
175 tasks（"全公司一天的工作"）
角色数
16 worker profiles：CTO / SWE / DevOps / Data Scientist / PM / HR / Finance / Sales / Marketing / Design / Legal / Admin / Researcher / Writer / Support / Executive Assistant
职业来源
O*NET SOC 大类直接采样，每个职业对应 ~10 任务
环境
自托管 GitLab / RocketChat / OwnCloud / Plane / 内网 Wiki —— 真公司用什么，benchmark 就跑什么
评分方式
Checkpoint（任务中途的中间状态）+ Final state（最终交付）；部分任务有 NPC 反馈
头条结果
Claude 3.5 Sonnet 完整完成率 24%，部分完成率 34%；Gemini 2.5 Pro 升至 30/39%（2025 更新）

方法学亮点：

  • 同一份"季度财务表"会出现在 财务桶（写季度报告）和 SWE 桶（修一个 BUG 才能让报表跑出来）—— 测试 agent 跨角色协作的能力。
  • 引入 模拟同事 NPC（也是 LLM 扮演）。Agent 必须主动用 RocketChat 提问、等回复。这模拟了真实办公的"协作摩擦"。
  • 评分包含 side-effect 检查（"修 bug 的过程中别把测试库给删了"）。

§2.4 旁证 · MedHELM (Stanford 2025)

CASE 2 MedHELM — 把医生这一职业拆成五个亚角色 Stanford CRFM · Nature Medicine 2025
论文
Nature Medicine
分桶
5 个临床任务类别：决策辅助 / 病历生成 / 患者沟通 / 研究 / 行政事务
为什么算职业派
桶的命名直接来自医生日常工作的子角色定位，不是底层能力轴

MedHELM 提示："职业"不一定要是 SOC 级别的大类，也可以是一个职业内部的"亚角色 (sub-role)"。这对 OpenClaw 很关键 —— 你的"digital_humanities" 实际上就是历史档案研究员的 sub-role，不是一个完整职业。

§2.5 权衡

✓ 优点
  • 可读性极佳：监管者/CEO/记者一眼就懂"能不能替换 HR"。
  • 生态效度高：任务长得就像真实工作。
  • 叙事友好：天然能挂上"AI 替代多少工作"的传播话题。
  • 采样有外部锚点：不是研究员拍脑袋，是劳工部的清单。
✗ 缺点
  • 能力高度重合：HR 写邮件 = Marketing 写邮件 = Writer 写邮件，桶之间信号冗余。Yehudai et al. 2025 综述称之为"over-fragmented partition"。
  • 文化漂移：英语"technical writer" ≠ 中文"技术作家"；制药业 SWE ≠ 互联网 SWE。
  • 难以诊断：当 Claude 在"财务桶"得分低，到底是数学差还是 Excel 工具用得差？职业桶不告诉你。
  • 组合性差：现实工作往往跨职业（FinOps、DevSecOps、产品经理 = ½PM + ¼SWE + ¼Marketing）。
对红沙的启示：职业派完美适配 Red Dust 的"四个邻居 + AURA" 设定。每个邻居自带职业人设，AURA 在不同决策点调用对应职业的 Core-X 任务，叙事张力天然。但要警惕：如果只有职业轴，玩家无法看到 AURA 在哪一类能力上失败。

§3 学派二 · 能力派 (Capability-based)

§3.1 核心命题与任务选择

命题

把 agent 拆成"由若干基础能力组合而成的系统"，每个能力都需要被独立诊断。

理论支点是认知科学的构念效度 (construct validity)传统：测一个东西，先定义清楚"这个东西"是什么。对应到 agent 上，这意味着先列一份"能力字典"，再为每个能力造一组孤立任务。

常见能力轴清单（综合 HELM / AgentBench / Yehudai 2025 / philschmid compendium）

  1. Reasoning / Planning — 多步推演、数学、规划。代表：ARC-AGI、GPQA、GAIA-L3。
  2. Tool Use / Function Calling — API 选择、参数构造。代表：BFCL、τ-bench、AppWorld。
  3. Coding / SWE — patch 生成、跨文件编辑。代表：SWE-bench (Verified / Pro / Multimodal)、SWE-Lancer。
  4. Computer / GUI Use — 桌面、浏览器操作。代表：OSWorld、WebArena、VisualWebArena。
  5. Web Information Seeking — 检索 + 综合。代表：BrowseComp、AssistantBench。
  6. Multimodality — 图像/视频/音频接地。代表：VWA、GAIA multimodal。
  7. Long-Horizon / Memory — 长轨迹、上下文保持。代表：UltraHorizon、LongCLI-Bench、SWE-Bench Pro。
  8. Reliability / Consistency — 多次重复的稳定性。代表：τ-bench passk。
  9. Safety / Policy Compliance — 拒绝、注入防御。代表：HELM safety、Anthropic SHADE。
  10. Communication / User Interaction — 澄清、谈判、对话。代表：τ²-bench。

任务选择逻辑

  • 每个能力轴单独设计探针。同一份原始素材常常会被改写成多套题，每套只测一个能力 —— 这是"消除混杂变量"的实验设计思路。
  • 任务规模追求 统计显著：一个能力轴下常常上百题以保证测量误差小。
  • 任务粒度 较细：一个 SWE-bench 题只验证一个 patch，不顺带让你写文档。

§3.2 分桶逻辑

分桶单位 = 能力轴。最常见的实现是二维矩阵：

  • HELM 样式：scenario × metric（场景 × 评价维度），如 "MMLU × accuracy"、"MMLU × calibration"。
  • AgentBench 样式：environment × capability，8 个环境分别测不同能力。
  • Yehudai 2025 综述提出：Evaluation Objective (behavior / capabilities / reliability / safety) × Evaluation Process (interaction / dataset / metric / tooling)。

§3.3 案例 A · HELM (Stanford CRFM)

CASE 3 HELM — Holistic Evaluation of Language Models Stanford CRFM · Liang et al. · 2022 起持续更新
论文
crfm.stanford.edu/helm
原始结构
16 个 core scenarios × 7 个 metrics（accuracy, calibration, robustness, fairness, bias, toxicity, efficiency）
关键观察
HELM 之前，每个模型平均只被报告在 17.9% 的 scenarios 上；HELM 之后这个数字升至 96%
关键设计
"全维度对所有模型应用统一评估"是其最大方法学贡献，不是发明新任务

HELM 不发明新任务，它收编已有任务。这是能力派的典型操作 —— 既然每个研究者都造自己的 benchmark，那就把它们拼成一张矩阵，统一报告。这种"meta-benchmark"思路对 OpenClaw 很有借鉴价值：你已经把六个上游 benchmark 拉进来了，缺的是统一的二维报告轴。

§3.4 案例 B · GAIA (Meta + HuggingFace)

CASE 4 GAIA — 三难度梯度 × 多能力混合 Mialon et al. 2023
论文
arXiv 2311.12983
任务规模
466 题
分桶
3 个难度 (L1/L2/L3) × 隐含能力组合（reasoning, multimodal, web, tool-use）
头条数
人类 92% vs GPT-4 + plugins 15%（2023）；2025 已被前沿模型推到 ~90%
评分
事实 exact match —— 答案是一个数字或字符串

GAIA 是难度梯度优先的能力派变种。它不显式按能力分桶（每道题都需要多种能力混合），但通过 L1→L3 的难度梯度让模型在"能力组合的复杂度"维度上排队。这是个偷懒但有效的设计：你不需要决定每道题主测什么能力，难度自动反映"agent 能否把多种能力拼起来"。

§3.5 旁证 · τ-bench (Sierra 2024)

CASE 5 τ-bench / τ²-bench — 把 reliability 提升为一级能力轴 Sierra · Yao et al. 2024 / 2025
论文
τ-bench arXiv 2406.12045 · τ²-bench arXiv 2506.07982
规模
~165 个零售/航空客服对话任务
关键创新
引入 passk 指标：同一题独立跑 k 次，全部成功才算过
观察
GPT-4o pass1 < 50%，pass8 < 25% —— 单次成功的 agent，八次有六次失败

τ-bench 显示了能力派的诊断力优势：把"可靠性"提升为正式维度，立即暴露所有 benchmark 都在掩盖的问题。这是职业派和用户行为派难以做到的 —— 它们的分桶单位是任务，passk 需要把同一个任务跑很多次，这跟职业桶的报告方式不兼容。

§3.6 权衡

✓ 优点
  • 诊断力最强：能直接说"你的 long-horizon 弱"、"你的 tool-use 强但 web-seeking 弱"。
  • 可组合可累加：能力轴正交时，可以预测新组合任务的表现。
  • 学术地位高：HELM 是 LLM 评估的事实标准，论文好发。
  • 科学方法成立：能力轴上的得分是 构念效度 意义上的"测量"，不是"评测"。
✗ 缺点
  • 生态效度低：孤立探针不长得像真实工作。"测了 reasoning 80 分"不等于"能写一份能用的报告"。
  • 受众窄：非 ML 受众听不懂"function calling F1 score"。
  • 能力字典本身有争议：reasoning 和 planning 算不算同一个？memory 是不是 long-horizon 的子集？
  • 叙事弱：很难在游戏/产品里讲"我现在在测 reasoning"。
对红沙的启示：能力派天然适配 AURA 的 PERCEIVE → HYPOTHESIS → PLAN → EXECUTE → VERIFY 推理轨迹 ── 这套五步框架本身就是一组能力轴，玩家看到的"AURA 在哪一步卡住"就是能力诊断结果。但能力派最大的问题是：玩家很难有"AURA 在干一件具体的事"的代入感。

§4 学派三 · 真实用户行为派 (User-behavior-based)

§4.1 核心命题与任务选择

命题

不预设"agent 应该会什么"，而是看真实用户实际让 agent 做什么，按那个分布造任务。

理论支点是产品分析 + 使用频率统计。这一派 2024–2025 才真正发展起来 —— 它需要大规模产品日志（ChatGPT、Claude.ai、Gemini App），所以只有大厂或它们的合作研究者能做到。

任务选择逻辑

  • 采样源：实测产品对话日志（隐私脱敏后）。
  • 意图聚类：通常用 LLM 做主题建模，先得到几十个 fine-grained class（"找菜谱"、"改简历"、"问健康"），再合并到 macro-category（"Practical Guidance"、"Writing"）。
  • 覆盖度优先：任务桶按使用频率从高到低排序，保证 top-N 桶能覆盖 ≥80% 流量。
  • 不追求难度均衡：用户问的多数问题是简单的，benchmark 也按这个分布反映。

§4.2 分桶逻辑

分桶单位 = 用户意图 macro-category。通常 3–7 个桶覆盖大部分流量。

  • 桶之间允许重合 —— 一个对话可能既是 Writing 又是 Practical Guidance。
  • 桶按 volume 加权：占 30% 的桶比占 5% 的桶在总分里权重更高。
  • 评分往往用 LLM-as-Judge（因为开放式回答多）或用户接受率代理。

§4.3 案例 · NBER w34255 "How People Use ChatGPT"

CASE 6 NBER w34255 — 1M+ 对话的意图分布 Chatterji, Cunningham, Deming, Hitzig, Ong, Shan, Wadman · Sept 2025
论文
NBER w34255 · OpenAI 经济研究 PDF
规模
1M+ 对话，覆盖 700M ChatGPT 用户
方法
分类器把对话标到 24 个 fine-grained class，再聚合为 7 个 macro-category
关键发现 (2025 mid-year)
三个 macro-category 覆盖 ~77% 总流量
Macro Category占比示例 fine-grained class
Practical Guidance~29%家教 / How-to / 创意 brainstorm / 健身建议 / 育儿
Seeking Information~24% (从 2024 的 14% 涨到 2025 的 24%)查产品 / 找菜谱 / 名人事件 / 替代搜索引擎
Writing~24% (从 2024 的 36% 降到 24%)编辑用户提供的文本 / 翻译 / 摘要 / 小说
注 其中 2/3 是编辑用户已有文本，不是从零生成
Technical Help~5% (从 12% 降)编程 / 数学 / 数据 —— 正在大规模迁移到 API / agent
Multimedia~3%图像/视频生成请求
Self-Expression~2%聊天 / 陪伴
Other~13%剩余

工作场景细分：在被标记为"work-related"的对话中，Writing 占 40%（生活场景中只占 24%）。这印证了 LLM 在职业场景里的"写作助手"定位。

§4.4 旁证 · Anthropic Economic Index

CASE 7 Anthropic Economic Index — 不同受众，不同分布 Anthropic · 2024 起持续更新
来源
economic-index · Jan 2026 Report
分类骨架
O*NET SOC 大类（注意：这是 职业派 的骨架，但应用方式是用户行为派 —— 用职业标签标记而不是采样对话）
关键发现
Claude.ai 上 "Computer & Mathematical" 占 37–40%；top 10 任务覆盖 24% Claude.ai 流量 / 32% API 流量

对照价值：Anthropic Index 和 NBER 用同一种方法（标记产品对话），但得出完全不同的分布。原因是：

  • ChatGPT 受众更"全人类"，所以 Writing/Practical Guidance 占大头。
  • Claude 受众更"开发者 + 知识工作者"，所以 Computer & Math 占大头。

这给用户行为派一个根本警告：你的"真实用户分布"取决于你测的是谁的用户。如果 OpenClaw 想以"真实场景"为卖点，必须明确目标用户群是哪一类，否则会得到一个"四不像"分布。

§4.5 权衡

✓ 优点
  • 覆盖广：top 5 桶能覆盖 ~80% 真实使用，benchmark 不会测一堆没人在乎的东西。
  • "体感"对得上：分桶名（Writing / How-to / Search）就是普通人对 LLM 的直觉描述。
  • 营销好讲：能直接说"我们测了用户最常用的 N 个场景"。
  • 有外部数据锚点：NBER / Anthropic Index 的分布是真实的，可引用。
✗ 缺点
  • 长尾困难场景被压缩：用户其实不常让 agent 干"复杂跨文件 SWE 任务"，但这恰恰是前沿模型的关键能力 —— 用户行为派会低估它。
  • 高频 ≠ 值得测：用户问"今天天气"几百万次，但每次都没难度，对 benchmark 没区分力。
  • 跨产品迁移性差：ChatGPT 的分布 ≠ Claude ≠ Gemini，研究者口径不统一。
  • 数据访问门槛：只有大厂能拿到对话日志，外部研究者只能引用，不能复现。
对红沙的启示：用户行为派最适合让"AURA 能干什么"对应到玩家的直觉。如果红沙的玩家就是普通游戏玩家（不是 ML 研究员），那 AURA 应该擅长 Practical Guidance（建议怎么分配水/电池）+ Seeking Information（从老报纸里找信息）+ Writing（帮你起草 SOS 广播稿）—— 这三件事正好对应 NBER 三大桶。

§6 对红沙单间生存背景的张力

本节仅指出张力，不开方案 —— 设计决策留给下一份文档 (18_REDDUST_BENCHMARK_REDESIGN_CN)。

张力 1 · 叙事友好性 vs 能力诊断力

红沙的核心机制（§16 §10.2）是：每个剧情事件 → AURA 跑一道 Core-X 任务 → 玩家看到推理过程 → 玩家决定是否采纳。这套机制对能力派非常友好（PERCEIVE→HYPOTHESIS→PLAN→EXECUTE→VERIFY 五步本身就是能力轴），但剧情挂钩需要职业派的人物感（陌生人敲门 → 数据分析 → 信任判断）。两者必须并存。

张力 2 · 玩家"看见 agent 在干什么"

这是用户提到的关键约束。三派各有各的"可见性"问题：

  • 职业派可见性：玩家看到"AURA 在帮我修风扇" —— 直观但低分辨率。
  • 能力派可见性：玩家看到"AURA 卡在 tool-use 那一步" —— 分辨率高但太抽象。
  • 用户行为派可见性：玩家看到"AURA 给我建议 / 帮我找信息 / 帮我写广播稿" —— 直觉对得上但和剧情挂钩偏弱。

张力 3 · 30 天积累的可信度

红沙宣称"30 天 = 一个 agent profile"。这只有在能力轴正交的前提下才成立 —— 否则你只是反复测同一个底层能力 30 次，profile 没新信息。这是能力派必须介入的硬约束。

张力 4 · 单间封闭场景的覆盖度

"单间生存"天然把任务空间压缩到几类：物资分配、设备维修、人际沟通、信息检索、危机决策。这恰好对应 NBER 三大桶 + 一两个长尾。所以用户行为派的覆盖逻辑跟红沙的物理空间天然合拍。

预告：下一份文档将提出"三轴对齐"的具体方案 —— 外层职业 (邻居人设 + Core-X) + 内层能力标签 (AURA 推理轨迹的五步) + 评估覆盖度参考用户行为分布 —— 既保留 §10.2 现有剧情挂钩，又新增能力雷达图和体感分桶报告。届时会附"哪些任务该砍、哪些该加"的具体清单。
