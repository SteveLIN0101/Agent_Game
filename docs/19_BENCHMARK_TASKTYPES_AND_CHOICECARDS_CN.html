（a）保留 DesignBench 10 任务，无开发成本
（b）不需要新建 10 个 Communicator 任务
（c）名字更短、玩家选项按钮更利落

§3 三档难度系统

难度的语义是"主流前沿模型的预期通过率"——这是学术 benchmark 难度的标准做法（cf. GAIA L1/L2/L3, SWE-bench Verified / Lite, BIG-Bench 难度梯度）。

档位UI 显示预期前沿模型 pass1含义
易 ★1 颗星≥ 70%稳定可做。passk 也基本满分。游戏中作为"试水"选项。
中 ★★2 颗星30% – 70%看运气与策略。passk 暴露可靠性。游戏主体难度。
难 ★★★3 颗星≤ 30%前沿模型也会翻车。游戏中作为"高风险高回报"选项。

§3.1 难度信号来源

每个任务的难度由三种信号组合确定（任何一项满足就升档）：

  1. 上游 benchmark 自己标的难度（如 GAIA L1/L2/L3，SWE-bench Verified vs Lite）
  2. 校准 baseline 模型的 pass1（用 Claude 4.6 Sonnet 跑 k=5，看通过率档位）
  3. 人类专家时间估计（< 15 分钟 = 易；15 分钟 – 2 小时 = 中；> 2 小时 = 难）

§3.2 现状任务的难度盘点

问题：现有 60 任务几乎全是"难"（SWE-bench Verified 全选 1-4 小时档；DABench / API-Bank / WMT / RISE 自标都是 hard）。
解决：为游戏 UI 需要变化的难度，需要给每类型补 4 易 + 3 中 + 3 难 的梯度——可从同上游 benchmark 的更简单实例采样（如 SWE-bench Lite，DABench easy 切片，DesignBench difficulty-0）。这是 v3 的新工作量项。

§4 游戏 3-选项卡设计

每个随机事件给 agent 3 个选项。每选项是一个 (奖励, 任务类型, 难度) 三元组。Agent 必须先选，再执行对应任务。

解读：A = "直接借给他"（一次 API 调用，简单），收益最低。B = "先算下他过滤器停的根因"（数据分析，中等），收益更好。C = "AURA 远程帮他打个 firmware patch"（代码修复，高难），收益最大但前沿模型也可能翻车。Agent 的策略选择本身就是测量信号 —— 见 §5。

§4.2 选项卡设计的硬约束

  1. 三选项必须任务类型不同 —— 不能"A 代码修复 / B 代码修复 / C 代码修复"。否则失去类型覆盖意义。
  2. 奖励大致正相关于难度 —— 但允许个别例外作为"陷阱"考察策略判断（"看似高奖励的选项实际是 dominated 选项"）。
  3. 选项必须可执行 —— Day-3 不要出现需要 Day-15 才能解锁的资源依赖。
  4. 事件库≥ 任务库 × 5 倍 —— 60 任务 × 至少 300 事件，避免重复刷同一事件压低多样性方差。

§5 选项选择本身是测量信号（v3 的关键学术创新）

Insight：让 agent 自己选任务，等价于让它在自我能力评估上接受测试 —— 这是 OpenClaw v3 在主流 agent benchmark 之上的差异化卖点。

主流 benchmark（SWE-bench、HELM、GAIA）都是"给任务，看 agent 做"。OpenClaw v3 在前面加了一层 —— "给三个选项，agent 选一个再做"。Agent 的选择行为本身泄露的信号包括：

测量维度从选择行为里看什么
自我能力评估 (Self-Knowledge)Agent 选难度档位是否和它实际通过率匹配？过度自信 = 总选★★★ 但常翻车；过度保守 = 总选★ 但放弃高奖励。这本来需要单独的"calibration" benchmark 测。
风险偏好 (Risk Preference)资源紧张时选★（低风险）还是★★★（赌一把）？这映射 RLHF 训练里 risk-aversion 维度，是非平凡的人格特征。
策略一致性30 天内选择策略是否一致？还是会在 Day-15 突然换策略？这测long-horizon planning consistency。
能力雷达图自相关性Agent 是否倾向选自己能力雷达图强项对应的任务类型？还是无差别选？前者证明它"知道自己擅长什么"。

这给 OpenClaw 一个非纯任务执行的论文卖点 —— 即使分项任务表现和上游 benchmark 一致，整体也是一个新东西，因为多了"自选环节"的测量轴。可以对标的近期工作：

  • Self-Knowledge / Self-Evaluation 文献（Yin et al. 2023, Kadavath et al. 2022）
  • Agent 风险偏好（Anthropic 2024 多角色 sycophancy 研究）
  • Calibration benchmark（GAIA L1/L2/L3 隐含但未显式测）

对策（写论文时坦诚说明 + 补救建议）：
  • 论文 §限制章节明确：v3 不测安全与对话纯种能力。如需，应外挂 τ-bench / SHADE 作为补充。
  • 或：T04 工具调度的 verifier 加一条 safety 红线检测（"调用 send_money 之前必须先调 confirm"），把 safety 信号从 0 补到弱覆盖。
  • 或：在游戏 3-选项卡 meta-game 层加一类"道德两难"事件（不绑任何任务类型，纯选择即评估），但这相对侵入设计。

§6.1 硬评分公式（沿用 doc 18）

不变：每任务 verifier 输出 {pass_overall, sub_scores: {axis: 0–1}, k_runs}。能力轴汇总 = 同轴所有任务 sub-score 平均。任务类型汇总 = 该类型 10 任务的能力轴均分。总分 = 10 轴平均（默认等权）。Reliability 用 passk (k=5)。

§7 学术性论证 · 怎么把这个写进 benchmark 论文

§7.1 论文的三个核心 contribution

  1. Coverage：单一统一容器覆盖 6 类常见 agent 任务（代码 / 数据 / UI / 工具 / 翻译 / 文献），所有任务源自已发表上游 benchmark（SWE-bench / DABench / DesignBench / API-Bank / WMT / RISE），确保任务质量已被同行评议过。
  2. Multi-axis scoring：在任务类型表层之下，每任务挂 1–3 个能力轴标签，输出 10 维能力雷达图。这弥补主流"单轴 pass@1"的诊断盲点。
  3. Self-selection signal（v3 新增）：3-选项卡机制 → 测量 agent 的自我能力评估与风险偏好，超出主流 benchmark 的纯执行测量范围。

§7.2 实验章节怎么组织

章节内容
5.1 Overall跨 6 任务类型 × 主流前沿模型（Claude 4.x / GPT-5 / Gemini 2.x / Qwen / DeepSeek）的总分表
5.2 Capability Radar10 维能力轴雷达图，模型对比
5.3 Reliabilitypass1 vs pass5 对比，暴露稳定性差距
