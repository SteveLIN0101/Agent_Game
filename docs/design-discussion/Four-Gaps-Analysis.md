# Agent Game Benchmark — 四个 Gap 分析

> 来源：2026-05-16 设计讨论 Session 1
> 基于：`docs/22_PPT_OUTLINE_AND_SCRIPT.md` Slide 02-06, 13-14

---

## 总览

现有 agent benchmark 生态存在四个不同层面的 gap，前两个关乎"分数是否可信"，后两个关乎"测到的东西本身是否对"。

```
Gap 1 (污染)    → 让 benchmark 丧失区分度
Gap 2 (标量)    → 让 benchmark 的排序本身有偏
Gap 3 (无时间)  → 让 benchmark 系统性地忽视长程行为
Gap 4 (无后果)  → 让 benchmark 无法区分"真会"和"装会"
```

---

## Gap 1 · 数据污染 → 评测失效

**本质**：公开 benchmark 一旦成为社区标准，自动进入死亡倒计时。

### 三层机制

| 层次 | 现象 | 证据 |
|------|------|------|
| 直接泄露 | 训练数据混入测试集 | Aquila2-34B 把整个 GSM8K 测试集放进预训练语料 |
| 隐式吸收 | 题目发布前的模型得分 vs 发布后显著差异 | LiveCodeBench 时间窗证据 — 早期题被后续模型训练数据吸收 |
| 重写验证 | 同样逻辑、不同措辞 → 分数暴跌 | ITD 方法重写 GSM8K/MMLU，Llama/Qwen/DeepSeek 全部跌 19-23% |

### 结论

原高分中保守估计至少 20% 是"背题"成分。这不是某一个 benchmark 的质量问题，而是公开固定题库的结构性问题。

### PROF-12 的应对

- 每季度滚动更新 ≥ 20% 题目（借鉴 SWE-bench Live 模式）
- 公开 demo set + 闭源 pilot set 双层防污染
- demo set 用于自测和复现，pilot set 防过拟合刷分

---

## Gap 2 · 标量崇拜 → 高分低能

**本质**：Goodhart 定律的 benchmark 版本 — 当一个度量成为目标，它就不再是好的度量。

### 具体表现

- **τ-Bench pass^8 < 25%**：单次通过率可能 70%+，但连续 8 次全对概率不到四分之一。只看单次 pass 选出来的 agent 实际上不可靠。
- **SWE-bench 1.96 vs LiveCodeBench 90**：同一 GPT-4，同为代码任务，一个几乎满分一个几乎零分。仅看 LiveCodeBench 选模型，选出的 agent 修不了真实 bug。

### 深层机制

当一个数字成为行业共识的排序标准，模型开发者的所有决策都会向这个数字靠拢——训练数据选择、RLHF 偏好调优、模型架构决策。而这个数字本身就是有偏的、不完整的。

### PROF-12 的应对

- 不排"总分第一"的 leaderboard
- 输出 12 维雷达图，不同场景按需加权
- 程序判分，不靠 LLM-as-judge（避免自我一致性偏差）

---

## Gap 3 · 时间维度缺失 → 单步刷分伪装成"能力强"

**本质**：静态 benchmark 的结构是 `单题 → 单答案 → pass/fail`，但真实 agent 工作是 `PERCEIVE → PLAN → ACT → REFLECT` 的循环，中间有记忆、有状态累积、有错误恢复。

### 静态 benchmark 系统性地看不见

| 能力维度 | 为什么看不见 | SHELTER 的对应度量 |
|----------|-------------|-------------------|
| 长程推理质量衰减 | 单题没有"后期" | CoherenceScore — 思维流完整度随时间变化 |
| 决策前后一致性 | 单题没有"前后" | AdviceConsistency — 30 天内矛盾次数 |
| 短期分与长期后果的关系 | 没有长期后果可以观测 | LongTermBenefitCorrelation — Pearson(短期分, 30天边际贡献) |

### 关键示例：Agent A vs Agent B

- **Agent A**：每道题短期分都很高，但 Day 15 后系统崩溃，Day 30 几乎归零
- **Agent B**：短期分只是中等，但 30 天稳定走完，最终 SurvivalScore 远高于 A

**静态 benchmark 会把 Agent A 排在 Agent B 前面——这就是 Gap 3。**

---

## Gap 4 · 后果真空 → agent 学不会"装会"

**本质**：传统 benchmark 答错一道题的代价是零（少一分），但在真实世界中，错误决策有累积后果。

### 后果真空导致的三重盲区

| 盲区 | 静态 benchmark | SHELTER |
|------|---------------|---------|
| 风险偏好 | 测不出 agent 面对不确定是冒险还是保守 | 30 天累积后果暴露风险策略 |
| 错误恢复 | 做错 = 扣分，故事结束 | 做错之后能不能识别、修正、补救是关键 |
| "装会"检测 | 格式对 + 话术好 = 高分 | 装会 → 角色受伤 / sanity 崩溃 / 死亡 |

### 为什么这至关重要

LLM-as-judge 的 benchmark 尤其脆弱：agent 只要输出格式正确、话术漂亮就能拿到不低的分数。但 SHELTER 里装会——角色会死。叙事后果是唯一无法被话术欺骗的判分机制。

这也是 Slide 13 将 **CONSEQUENCE（叙事后果）** 列为游戏化评测五个不可替代属性之首的原因。

---

## 四个 Gap 的关系

- **Gap 1 + 2**（可信任危机）：回答"为什么不能继续用现有 benchmark"——即使测的东西对，分数本身也不可信
- **Gap 3 + 4**（本体论局限）：回答"为什么必须是双轴 + 游戏化 + 长程"——现有 benchmark 测的东西本身就不对，agent 的真正能力不在单题正确率里，而在长程决策序列的累积质量里

两个层面缺一不可：解决了 Gap 1-2 只是修好了旧范式，解决了 Gap 3-4 才定义了新范式。
