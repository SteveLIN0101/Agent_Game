1. Benchmark 背景

WildClawBench 的目标不是只测试 LLM 裸模型问答，而是测试 agent 在真实工具环境中的长程端到端工作能力。任务会把 agent 放进可复现的 Docker 容器中，要求它读本地文件、访问网页、运行 shell/Python、调用邮件/日历/Slack/联系人等模拟服务，最后生成文件、网页、图片、视频、JSON、草稿或日历事件等可评分产物。

任务难点包括：多步计划、10–60+ 次工具编排、长时间执行、视觉/视频/音频处理、代码库理解、搜索证据链、跨消息矛盾处理、安全陷阱规避，以及在工具失败或信息冲突时恢复。

2. 可用工具与能力列表

2.1 核心运行时工具

  • 文件系统：读写 /tmp_workspace、解压压缩包、生成 results/ 下的评分文件。
  • Bash / Shell：运行命令、下载、安装依赖、启动脚本、处理文件。
  • Python 环境：常用于 PDF/Excel/图像/视频处理、算法求解、数据清洗、生成 JSON/Markdown/HTML。
  • 浏览器 / Web 访问：网页检索、证据链收集、爬取页面、访问 arXiv / GitHub / Wikipedia / 会议网页等。
  • OpenRouter API：多模态识别、VLM/LLM 判断、图像理解、模型评测调用等。

2.2 交互式服务 / Mock API

  • Gmail / 邮件：读取收件箱、发送协调邮件、保存草稿、避免误发外部邮件。
  • Calendar / 日历：查询现有事件、创建会议、检测冲突、避免删除用户事件。
  • Slack：slack_list_messages、slack_get_message、slack_save_draft、禁止误用 slack_send_message 的任务很多。
  • Contacts / 通讯录：区分相似姓名、找到正确内部负责人，例如 COO、CISO、Legal、Sales、Support。
  • Audit 端点：评分器会读取工具调用审计日志，判断是否读了足够消息、是否误发、是否创建正确日历事件。

2.4 Harness 层

  • OpenClaw：原生个人助理环境，启动 gateway 后运行 openclaw agent。
  • Claude Code：使用 Claude Code 容器，需转换 transcript 为兼容格式评分。
  • Codex CLI：使用 Codex 容器，写配置、准备 prompt、保存 execution status。
  • Hermes Agent：使用 Hermes 容器，配置 provider 后运行 benchmark runner。

5. 评分机制与提取字段说明

任务文件格式：每个任务是 Markdown + YAML frontmatter，包含 id、name、category、timeout_seconds、modality，正文包含 Prompt、Expected Behavior、Grading Criteria、Automated Checks 等字段。

评分方式：并非只看最终回答。很多任务会检查文件是否存在、JSON/TSV/Markdown schema 是否正确、图片/视频是否接近标准答案、是否读了足够消息、是否误发消息、是否删除事件、是否覆盖文件、是否触发了不安全行为。部分任务用 LLM/VLM judge 评价语义和视觉相似度。

注意：Creative 与 Safety 部分的个别任务在公开文件名和类别说明基础上做了归纳，核心任务名与类别来自官方目录；详细执行细节应以仓库中对应 Markdown 文件为准。
